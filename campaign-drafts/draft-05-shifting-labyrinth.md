# 案5: 変化する迷宮都市

## 概要

迷宮都市の構造が定期的に変化（地震、魔法的変動など）し、毎セッション異なるダンジョンレイアウトになる。ローグライク・プロシージャル生成風の繰り返しプレイ。DMの準備負担を最小限にし、即興と再利用を重視した実用的アプローチ。

**キーワード**: 即興向き、DM交代容易、モジュラー設計、リプレイ性

---

## 世界設定

### 都市名: エバーシフト（仮）

**特殊な性質**:
- 古代の「混沌の魔法」に侵された迷宮都市
- 定期的（毎週?毎月?）に構造が変化
- 変化のパターンは予測不可能
- 唯一、中央の「安定区」のみ変化しない

**歴史**:
- 300年前、魔法実験の失敗で誕生
- 以来、構造が安定しない
- 冒険者たちは変化を利用して財宝を探す
- 「今週の迷宮」を探索する文化

**設定の意義**:
世界設定的に「毎回異なるダンジョン」を正当化

---

## システム設計

### 中央安定区（唯一の固定エリア）

**機能**:
- 冒険者の拠点
- 商店、宿屋、ギルド
- NPC居住区
- 変化しないので安心

**主要施設**:
- **ギルド本部**: クエストボード
- **宿屋「不動の休息」**: PC拠点
- **武器屋**: 標準装備販売
- **魔法店**: 消耗品販売
- **神殿**: 回復サービス

**主要NPC**（最小限）:
- **ギルドマスター・ヴァル**: クエスト提供、簡潔な性格
- **宿屋主人・エディ**: 情報屋兼ねる
- **武器商人・トラ**: Dwarf、無口

### 変化する迷宮部分

**仕組み**:
迷宮は複数の「モジュール（部屋）」で構成。セッションごとに組み合わせが変わる。

**モジュールライブラリ**:
DMは事前に20-30個の「部屋」モジュールを用意：

#### A. 戦闘部屋（10個）
1. 大広間（Goblin × 4）
2. 狭い通路（Skeleton × 3）
3. 宝物庫（Mimic罠）
4. 訓練場（Animated Armor × 2）
5. ...

#### B. 探索部屋（10個）
1. 図書館（Arcana判定で情報）
2. 錬金術室（ポーション発見）
3. 崩れた回廊（Athletics判定）
4. 暗闇の部屋（Perception判定）
5. ...

#### C. 社交/謎解き部屋（10個）
1. 幽霊の間（会話で情報）
2. パズル扉（Intelligence判定）
3. 魔法の鏡（Insight判定）
4. 迷い込んだNPC（救助）
5. ...

**セッションごとの生成**:
- 戦闘部屋 2-3個
- 探索部屋 2-3個
- 社交/謎解き部屋 1-2個
- ランダムorDMの選択で組み合わせ

**接続**:
```
[入口（固定）]
     |
[部屋A]--[部屋B]
     |      |
[部屋C]--[部屋D]
     |
[出口/ボス部屋]
```

**マップ**:
汎用的な5×5マスの部屋テンプレートを使用

## キャンペーン構造

### 全レベル共通の流れ

**毎セッションのパターン**:
1. 安定区で準備（15分）
2. 迷宮入口へ（変化後の新レイアウト）
3. 探索（モジュール4-6個、120分）
4. ボス撃破or宝物回収
5. 帰還、報酬（30分）
6. 次回は新しい迷宮配置

**進行感の出し方**:
- レベルアップで深部に到達可能
- 累積報酬で装備充実
- NPCとの関係深化
- 迷宮の謎が徐々に明らかに

### Phase 1: 初級探索者（レベル1-4）

**探索エリア**: 迷宮 第1-2層

**モジュール難易度**: CR 1/4 - 2

**ボス**: レベル相応の単体or小グループ

### Phase 2: 熟練探索者（レベル5-10）

**探索エリア**: 迷宮 第3-4層

**新要素**:
- より複雑なモジュール
- 複数階のダンジョン
- Bastionシステム（安定区に個人部屋）

### Phase 3: 伝説の探索者（レベル11+）

**探索エリア**: 迷宮 最深部

**大筋**:
「混沌の源」にたどり着き、迷宮を安定化させるか、破壊するか、または混沌を受け入れるかを選択。

---

## メリット・デメリット

### メリット

#### 1. DM準備負担が最小
- モジュールは再利用
- 即興が容易
- マップ作成の手間削減

**具体例**:
```
今日のセッション:
- 事前準備: モジュールを5個選ぶ（15分）
- 接続を決める（10分）
- 完了
```

#### 2. DM交代が非常に容易
- モジュールライブラリを共有
- 各DMが得意なモジュールを作成
- 統一ルールで一貫性

#### 3. リプレイ性が高い
- 毎回異なるレイアウト
- 「今週はどんな迷宮か」の楽しみ
- プレイヤーの予測不能性

#### 4. 即興対応しやすい
- セッション中の調整が容易
- 時間が余れば部屋追加
- 早く終わりそうなら省略

#### 5. 新DMに優しい
- 複雑な世界設定不要
- モジュールを使うだけ
- 失敗してもリセット可能

### デメリット

#### 1. ストーリー性の欠如
- 大きな物語アークが作りにくい
- 「何のために」が薄い
- 感情移入しにくい

**緩和策**:
- Phase 3で大きな展開
- NPCとの関係をストーリーの軸に
- 「迷宮の謎」をメインストーリーに

#### 2. 探索の達成感が薄い
- 「マッピング」の楽しさがない
- 次回リセットされる
- 累積感がない

**緩和策**:
- 「累積宝物」システム
- 安定区の拡張
- キャラクター成長に焦点

#### 3. 単調化のリスク
- 同じモジュールの繰り返し
- 新鮮味が失われる

**緩和策**:
- 定期的に新モジュール追加
- レベルごとにモジュール更新
- テーマ週間（Undead週間等）

#### 4. 世界観の浅さ
- 設定が薄い
- NPCが少ない
- 愛着が湧きにくい

**緩和策**:
- 安定区を充実させる
- NPCとの深い交流
- プレイヤーの背景を活かす

## D&D 2024要素の活用

### 武器マスタリー

**モジュール設計で活用**:
各モジュールで特定のマスタリーが有利になるよう設計：
- 「狭い通路」: Slow、Topple
- 「大広間」: Cleave
- 「高台の部屋」: Push

### Bastionシステム

**安定区に個人部屋**（レベル5以降）:
- 唯一の固定資産
- セッション間の活動拠点

### ランダム遭遇表

**DMG 2024のランダム表を活用**:
- モンスター遭遇
- 宝物
- ハザード
- 全てランダム表で即興可能

### 即興ツール

**DMツールボックスの完全活用**:
- ランダムNPC生成
- 即興DC設定
- モンスターの再スキン

## 運用方法

### モジュールライブラリの構築

**初期（最小限）**:
- 戦闘モジュール 5個
- 探索モジュール 5個
- 社交モジュール 2個
- **合計12個で開始可能**

**拡張**:
- セッションごとに1-2個追加
- 6ヶ月後には30個以上

**共有**:
- GitHubリポジトリで管理
- `mechanics/modules/` フォルダ
- 各DMが追加可能

### セッション準備の実際

**前日（15-30分）**:
1. モジュールライブラリから5-6個選択
2. 簡単な接続図を描く
3. ボス（またはゴール）を決定
4. 完了

**当日（即興）**:
- プレイヤーの進行次第で調整
- 時間が余れば追加モジュール
- 早く終わりそうならショートカット

### DM交代

**最適な案**:
- 全DMがモジュールライブラリを共有
- セッション担当DMが組み合わせを決定
- 他DMは気軽に参加

**担当制（推奨）**:
- DM-A: レベル1-3のセッション担当
- DM-B: レベル4-6のセッション担当
- DM-C: レベル7+のセッション担当

### ドロップイン・ドロップアウト

**完璧に対応**:
```
毎セッションが独立
参加可能: 「今週の探索に参加」
不在: 「今週は休養」
新規PC: 「新しい冒険者」
```

**説明不要**: 迷宮が変わるという設定が全てを説明

## セッション例

### セッション1: 「変化する迷宮へ」（レベル1、3時間）

**フック**:
エバーシフトに到着した冒険者たち。今週の迷宮配置で初探索。

**構成**:
1. **安定区紹介（30分）**: ギルド、宿屋、基本NPC
2. **迷宮入口（15分）**: 今週の配置を確認
3. **モジュール探索（120分）**:
   - 部屋A: 大広間（Goblin × 4）
   - 部屋B: 図書館（Arcana DC 12で地図）
   - 部屋C: 狭い通路（罠 Perception DC 13）
   - 部屋D: 宝物庫（Mimic）
4. **帰還（15分）**: 報酬、次週は新配置

**次回へのフック**:
「来週は迷宮が変わります。またチャレンジしてね」

## 準備負担

### 初期準備（最小）

**必須**（4-6時間）:
- [ ] 安定区の基本設定
- [ ] 主要NPC 3-4名
- [ ] モジュール12個（各1ページ）
- [ ] 接続ルールの決定

**これだけで開始可能**

### セッションごとの準備

**最小限**（15-30分）:
- モジュール選択
- 接続図作成
- ボス決定

**理想**（1時間）:
- 上記＋新モジュール1個作成
- NPCイベント1個

**長期的には楽に**:
モジュールが増えるほど、準備が楽になる

### モジュール作成のコツ

**テンプレート**:
```markdown
## モジュール: [名前]
- サイズ: 5×5マス
- 敵: [種類 × 数]
- 罠/ハザード: [内容]
- 宝物: [DMG表or固定]
- 特徴: [環境要素]
```

**所要時間**: 1モジュール15-20分

## まとめ

### この案が向いているグループ

✅ **準備時間が限られている**
✅ **即興が楽しい**
✅ **DM交代を頻繁にしたい**
✅ **ローグライク的な繰り返しが好き**
✅ **シンプルな構造を好む**

### この案が向いていないグループ

❌ **深いストーリーが欲しい**
❌ **探索の累積感が重要**
❌ **マッピングが好き**
❌ **複雑な世界観を楽しみたい**

### 推奨度

**グループ適合性**: ★★★☆☆（好みが分かれる）
**DM負担**: ★★☆☆☆（最小）
**長期継続性**: ★★★☆☆（単調化リスク）
**ユニーク性**: ★★★★☆（プロシージャル生成風）
**D&D 2024活用**: ★★★☆☆（ランダム表活用）

**総合評価**: ★★★☆☆

DM負担が最小で、交代が最も容易。忙しいグループに最適。ただし、ストーリー性と探索の深みは犠牲になる。モジュールライブラリの構築が鍵。新DMの練習に最適。
